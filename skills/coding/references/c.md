# C

- 从实际编译选项和目标平台确认 C 标准、ABI、警告级别和库能力。新增接口沿用项目的错误码、返回值和所有权约定。
- 调用处应能辨认谁拥有缓冲区、文件描述符或句柄，何时移交，失败时由谁释放。仅在成功时交付已初始化的资源，或遵循已有的部分成功契约。资源逐步获取时，统一清理已获取部分可减少遗漏。
- 缓冲区接口让调用者明确容量、有效长度、单位和终止符是否计入。来自外部的长度先核对取值和容量，在加法、乘法或窄化转换前确认结果可表示。检查后的值和真正使用的值应来自同一输入。
- 用已有错误机制保留根因。只有接口契约允许读取 `errno` 时才读取，在后续调用可能覆盖它前记录。按 API 契约处理部分读写和中断。
- 优先在现有测试入口验证正常输入、恰好到边界和相关失败路径。对于资源操作，核对失败后的返回值、输出参数以及资源状态。宿主机验证后，目标相关的 ABI、对齐或时序继续用项目的目标构建和测试确认。
