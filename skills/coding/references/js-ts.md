# JavaScript 和 TypeScript

- 按仓库的运行时版本、模块格式、包管理器、`tsconfig` 和验证命令编写。保持已有 JS 或 TS 边界和 API 约定。
- 外部输入在进入业务逻辑前做运行时校验，优先复用已有解析器或 schema。TypeScript 可从 `unknown` 收窄，JavaScript 用同一边界的显式检查。类型断言只能表达已有证据。
- 区分缺失、`null`、空字符串、`false` 和 `0`。按契约决定默认值及序列化行为。用普通字段或判别联合表达互斥状态，使每个状态只暴露适用的数据。
- 从调用处确认 Promise 是等待、返回还是有明确负责方的后台任务。把 rejection 交给已有错误边界处理。批量并发时根据契约选择失败传播方式，验证失败后已经完成的副作用如何处理。
- 用模块公开函数或实际运行时入口测行为。时钟和网络优先用项目已有的替换机制。变更类型契约时运行项目类型检查，涉及外部输入、序列化或异步结果时同时运行对应行为测试。
