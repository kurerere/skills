# Go

- 先看 `go.mod`、构建标签、已有包边界和测试命令。沿用包内公开契约及调用方实际依赖的错误语义。
- 处理返回的错误。需要补充操作上下文且调用方应能检查原始错误时，用 `%w` 包装，并用 `errors.Is` 或 `errors.As` 判断。包装会暴露底层错误身份，需要保持 API 边界时转换为已有的领域或包级错误。
- 传播调用方的 `context.Context`。创建可取消上下文后，由负责其生命周期的一方在退出路径调用取消函数。启动 goroutine 前确定谁负责停止、谁等它退出、谁拥有通道的关闭权。取消测试用明确同步信号驱动，避免依赖固定睡眠。
- 在调用方确有多种实现或需要隔离边界时定义小接口。普通包内协作优先沿用具体类型。用结构体字段、构造入口和方法表达有意义的状态约束，按包约定处理零值。
- 回归测试优先走正常包入口。先用聚焦的 `go test ./path/to/pkg -run '^TestName$' -count=1` 验证，再跑受影响包。只有多组输入共享相同验证结构时才用表驱动测试。改动共享状态或 goroutine 时，目标环境支持的情况下运行相关包的 `-race` 检查。
