# 简化代码：减少追踪层数和需要记住的状态

让读者少追踪调用层、少记住状态、少维护重复决策。以理解和修改代码所需的工作衡量简化收益，行数、函数长度和嵌套深度用于发现线索。

## 沿实际行为读代码

从用户指定的代码开始；未指定时，处理当前任务的改动及相关新文件。沿调用者和依赖理解输入、结果与副作用，找到项目已有实现和验证入口。只要求评审时，交付候选与依据。

简化保持返回值、错误语义、公开接口、副作用及顺序、资源释放和既有兼容要求。调查可以跨模块，修改围绕目标展开；独立缺陷与行为变更另行处理。

## 寻找可以消失的结构

优先消掉整段逻辑，再调整局部表达。按实际代码选择切入点：

| 方向 | 判断什么 |
| --- | --- |
| 现有能力 | 依次找项目实现、标准库或平台、已安装依赖，用行为等价的能力替代手写逻辑。 |
| 重复决策 | 集中同一条规则，让调用者直接使用结果。 |
| 冗余状态 | 从已有数据推导值，消掉维护同步的字段、分支、事件和缓存。 |
| 多余间接层 | 内联只做转发的包装和适配，让有用的边界直接显现。 |
| 数据表示 | 找出必须始终成立的不变量，用贴合领域的类型和结构消掉非法组合与成组分支。 |
| 遗留结构 | 删除失去用途的代码、临时兼容、调试残留和孤立引用。 |
| 局部表达 | 理顺控制流，让命名表达意图、相关逻辑就近，删掉复述代码的注释。 |

同时减少跳转和状态负担：缩小可变状态的作用域，让输入、输出和资源归属在调用处可见。抽象的价值在于隐藏复杂机制、表达领域概念或承载有效边界；据此决定抽取或内联。

合并维护同一规则、具有相同变化原因的重复逻辑。新结构应实际减少概念、重复规则或状态协调；清晰、局部的直接写法本身就是好结果。

## 用消融落实简化

对有价值的候选尝试删除、内联、合并或替换，回答“去掉它，具体什么会坏”。用调用关系、契约和运行结果检验这个假设，做成小步改动。

- 死代码沿动态调用、注册和外部消费者核实用途；兼容路径结合调用者、持久化数据和部署版本判断。
- 重复校验追溯到实际承担保证的边界，确认相关入口都经过它，保留有效的安全检查。
- 平台替换和执行方式调整，直接比较值转换、错误、顺序和资源语义。

测试结果与代码证据一起支撑删除判断，测试未覆盖的用途仍需核实。

## 验证行为与收益

改动前运行相关验证取得基线；关键行为缺少保护时补刻画测试、基线回放或等价检查。改动后复跑同组验证，按影响补充构建和静态检查。

保留证明功能有效的测试。验证失败时修正或只撤回本次引入的问题，保留用户已有改动。

重读结果，检查读者少追踪了什么、少记住了什么。留下行为成立且收益明确的改动，撤回只改变形式的折腾。已有结构合适时直接说明。

交付说明消除的复杂度、验证结果及影响结论的未验证项。
