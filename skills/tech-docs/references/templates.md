# 文档类型与内容取舍

以下是选择内容的参考，不是必须填满的模板。沿用项目已有结构；简单任务直接写清结果与必要依据。用户明确要完整手册时，也不能借精简省掉执行所需信息。

| 文档 | 读者要回答的问题 | 可能需要的材料 |
| --- | --- | --- |
| 操作手册 / SOP | 如何执行，怎样知道成功，失败怎么办？ | 适用环境、权限与依赖、步骤、结果判定、失败诊断、恢复方式 |
| 架构方案 / RFC | 解决什么问题，为什么这样选，代价是什么？ | 目标与约束、现状中影响决策的事实、候选方案、选择依据、风险、尚待验证的假设 |
| 故障复盘 | 发生了什么，影响谁，确认了什么原因，怎样减少复发？ | 影响范围、关键时间与证据、已确认与未决因果、处置效果、后续动作与验证方式 |
| 技术验证 / 压测 | 在什么条件下验证了什么，结果覆盖到哪里？ | 版本与环境、输入与方法、判定标准、原始结果摘录、边界及未覆盖项 |
| 接口文档 | 如何调用，允许什么输入，得到什么结果，如何处理错误？ | 协议与认证、字段约束、默认值、调用示例、返回与错误行为、使用限制 |
| 交付 / 发版说明 | 本次改变什么，谁需要采取什么动作？ | 行为变化、兼容影响、适用环境、升级与回退、已知限制 |
| 移植 / 适配说明 | 改了什么，为什么改，目标上能用到什么程度？ | 目标与工具链、平台差异、必要改动的依据、构建和运行结果、未验证项 |

按场景选择证据。现状说明可来自源码与配置，性能结论需要对应测量，设计可以使用明确标注的估算，外部约束可以来自用户或协议。没有数字时不编造，尚未确定的负责人、日期和结论保留为未决。

## 短文档也可以完整

一次验证可能只需：

```markdown
# <验证对象>

<结论及适用范围；证据不足就说明尚不能判断。>

<决定结论的环境、输入、方法与实际结果。>

<影响使用的限制与后续需要确认的内容；没有则省略。>
```

较长文档按读者查找方式拆节，不必照搬上述顺序。图、表、数据摘录和来源链接只在有助于理解或复现时加入。
