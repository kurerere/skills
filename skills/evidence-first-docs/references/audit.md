# 交付前门禁

逐条自答，全部为"是"才交付。

1. 每条命令、每个参数都在目标环境执行过？未执行的已标注档位或移出操作步骤？
2. 每个数字、版本号、路径都来自实际输出？
3. 读者只用这一份文档，能否从第 1 步走到目标？不依赖口头补充与外部资料。
4. 有无段落是在证明"我做过"而非"你要怎么做"？
5. 已知限制与未解决问题是否写明，且没有被写成已解决？
6. 版本约束、前置条件、权限要求是否写在正文，而非附录或脚注？
7. 份数是否最少？能否合并为一份？
8. 章节是否按读者动作顺序？任意一章删掉是否会破坏后续？
9. 同一概念是否全文只有一个名字？
10. 有无口语词、自评、情绪词、铺垫段、空洞小结？

## 反模式对照

| 反模式 | 现象 | 处理 |
| --- | --- | --- |
| 背景铺垫 | 开头两段讲行业趋势 | 删，第一句给读者第一条信息 |
| 三段式总结 | 每节末"通过以上……" | 删 |
| 自证式叙述 | "我试了 A，又试了 B" | 改为"已验证：A 可行；B 失败，原因为……" |
| 证据淹没正文 | 正文夹杂大段日志 | 正文留一句结论，日志进附件 |
| 未验证写成确定 | "通常需要先配置 X" | 标注档位，或实测后改确定 |
| 免责式收尾 | "以上仅供参考" | 改为明确适用范围 |
| 多份散落 | 手册 + 报告 + 说明互相引用 | 合成一份，其余归档 |
| 表格承载叙述 | 单元格写完整句子 | 改段落 |
| 口语化 | "这里有个坑" | "此处存在版本约束：……" |
| 隐藏失败 | 只写成功路径 | 补"常见问题"与"回退" |

## 高风险操作附加门禁

凡涉及改系统配置、覆盖、删除、升级：

- 操作前是否有备份命令，且备份路径可查？
- 是否有可执行的回退步骤（不是"重装系统"）？
- 是否标注了不可逆操作？
