# SylixOS 命令行工具移植

先读取当前项目的 `AGENTS.md`、受影响命令的源码和 man 手册、公共兼容头文件、Makefile 与已有测试。保留无关改动；若存在 `.codegraph/`，按项目约定用 CodeGraph 定位符号和调用关系。

## 确认任务与实现边界

- 新功能、行为变更或重构：明确目标、职责边界、依赖方向和验收条件，按可独立验证的切片推进。
- Bug、崩溃、挂起或回退：先复现、收集证据、定位根因，再提出修复方案和回归验证。
- 保留原 Unix/POSIX 命令的参数、输出、错误语义和退出状态。平台差异集中在既有兼容层或最小条件分支，优先复用公共函数。
- 测试外部行为，不为测试暴露内部实现。遵循项目的 C/C++ 规范，不引入未经确认的外部依赖，不添加装饰性或步骤性注释。
- 并行任务应有明确文件范围；集成、冲突处理、构建和同一板卡上的操作保持串行。

## 构建与验证

使用项目 Makefile；采用以下约定的项目按顺序执行：

```text
make format
make config
make build
```

安装、上传或清理仅在任务需要时执行相应目标，不绕过 Makefile 调用 CMake、Ninja 或编译器。失败时保留原始错误并定位原因。

每个切片验证正常、错误和边界行为，检查差异中的规范与回归风险。涉及系统调用、文件系统、信号、进程、网络或终端行为时，在项目指定的 SylixOS 目标上复核；主机结果不能替代目标验证。纯文档或机械修改执行相应检查，说明未运行的测试。

板卡传输与命令执行遵循 `$sylixos-ext-skill`；崩溃、挂起和线程诊断遵循 `$sylixos-gdb`。地址、端口、路径和凭据来自当前任务或项目配置，不复用其他工程的示例。
