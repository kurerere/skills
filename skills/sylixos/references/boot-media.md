# SD 启动盘与启动失败排查

板子上电或复位后启动失败、串口日志停在加载阶段时读取。目标侧命令仍按 [board-operations.md](board-operations.md) 与 [shell.md](shell.md)。

## 先定位失败阶段

按串口日志从前往后分阶段确认，不急着怀疑板卡或镜像：

- loader 阶段：若目标日志有 SPL、FIT 镜像哈希校验，校验通过只支持对应镜像在该项检查下符合预期；加载位置、执行结果与后续阶段另按当前目标核对。
- 文件加载阶段：`reading <file>` 后出现 `Invalid FAT entry` 且读出字节数不足时，先按加载不完整处理，检查簇链、读取错误及该版本 bootloader 的 FAT 实现。后续 Synchronous Abort 的原因仍需结合实际加载与执行情况核对。
- 判定方法：比对当前目标日志里的 "bytes read"、对应文件的实际大小和镜像内容；阶段标志、路径、大小及哈希从本次目标取得，样本数值不作为现场验收条件。日志可定位调查方向，根因由镜像结构、哈希与当前实现共同确认。

## 关键认知：fsck 通过 ≠ bootloader 可读

FAT32 表项低 28 位是簇链，高 4 位是保留位。操作系统按规范只取低 28 位，简化版 bootloader 可能拿整个 32 位做合法性判断，遇到高 4 位非零或超出范围的值即报 Invalid FAT entry 并截断读取。

仅高 4 位保留位不同的表项，按低 28 位解释时可能得到相同簇链；FAT 副本差异或数据误写也可能改变低 28 位，须分别检查。fsck 的检查范围取决于工具版本与选项；主机检查通过不能证明目标 bootloader 可读，其合法性判定以该版本实现为准。

## 取证

构造样本用于验证方法；现场处理从目标介质重新取证，修复副本必须由本次现场镜像生成。判定所用的文件清单、大小、哈希和日志须对应同一目标与版本。

1. 先把启动文件全量备份并记录哈希。
2. 导出该分区的原始镜像（只读，不改盘）。

第 3–5 步可用 `python3 <SKILL_DIR>/scripts/fat_check.py check <分区镜像> --path /<启动文件>` 辅助；与串口日志、bootloader 实现及备份哈希的核对须另行完成。脚本先核对 BPB、镜像范围与 FAT 容量，再报告保留位非零的表项、多份 FAT 的差异、按 32 位整值判断时在第几簇截断及约读到的字节数。只有簇链与实际字节数完整时才给出重建的 SHA-256。整盘镜像用 `--offset` 指定分区起始字节。退出码 0 表示本次检查未发现问题，1 表示发现异常，2 表示输入或解析失败；该检查只覆盖镜像结构，启动结论以上板验证为准。脚本只读；手工步骤如下，用于核对脚本结果或脚本不适用时：

3. 解析 BPB 定位 FAT 区与数据区；逐表项检查三类异常：链中间出现空闲值（≤1）或结束标记（≥0x0ffffff8）、保留位非零、多份 FAT 副本不一致。
4. 从目录项起始簇沿链走，找到第一个非法表项，把断点位置换算成字节偏移，与串口日志核对；位置一致后，结合当前 bootloader 的读取逻辑确认原因。
5. 离线验证修复方案再写回：按掩码修正表项后沿链重建文件字节，与备份哈希比对。一致说明低 28 位链接本来就完好，只需清位，文件数据可保持不动。

## 修复选项

按当前可用工具与权限选择，不定死某一条：

- 只改 FAT 表：所有表项保留位清零，以活动 FAT 为基准同步其余副本，写回分区镜像。`fat_check.py fix <分区镜像> <新镜像>` 生成这样的副本（以 FAT#1 为准，不覆盖已有文件）；FAT 镜像标志指定了其他活动 FAT 时不要用它。分区表、其它分区和文件数据都不动。写回前必须先在镜像上验证全部链完整、文件哈希一致。
- 重格式化该启动分区再拷回文件：前提是文件已备份并校验，重建后簇链干净。
- 原厂工具重制启动盘：先核对工具、镜像与目标板及介质的适用性，备份其覆盖范围内的数据；重制后复查实际布局、文件内容并上板验证。

写回盘后重新抓取 FAT 区确认表项干净、两份一致、链完整，再上板验证；修复判定以复查结果和上板表现为准。

## 边界与预防

- FAT 修补只修改指定启动分区；重格式化或原厂工具重制的覆盖范围以实际操作为准。同卡上的根文件系统分区若无可用的主机检查工具，启动恢复后如系统仍异常，用目标系统工具另行核查根分区状态。
- 同类卡上的启动文件若由厂商/板载工具写入，保留位带脏可能再次出现；修复只保证当前状态。
- 写完启动盘后正常卸载再断电。异常复现时继续核对写盘工具、介质、供电及 bootloader 实现；0 字节文件和孤儿簇可作为异常线索，不能单独确定原因。
