# 目标 Shell 与命令字符串

先核对实际命令解释器。SylixOS 内置 ttinyShell 与 POSIX sh/bash 的语法不同；应用也可能启动另外的解析器。startup.sh、shfile、system/popen 等具体由谁解析，须检查当前配置和调用路径，不能只凭系统名判断。

## ttinyShell 参考

仅在确认使用对应 ttinyShell 时应用下述历史语法，细节以当前手册、目标 help 和低风险验证为准。

- 一行一条命令，参数用空格分隔；含空格的参数用双引号。
- 历史版本支持 `${VAR}` 展开及 `NAME=value` 环境设置，不把 `$?`、`$!`、位置参数和算术展开当作可用功能。区分系统环境修改与进程环境，避免改动影响其他程序。
- 首个有效字符为 # 可注释整行；尾部反斜线用于续行。转义规则要查当前手册，双引号内的转义也可能产生真实换行。
- 历史版本尾部 & 为异步执行，^ 为在新线程同步执行；这不等同于 POSIX 作业控制。
- shfile 是逐行命令批处理，不默认支持条件、循环、函数和变量作用域。

不要默认使用管道、通配符、分号/&& 链接、命令替换、单引号或 sh -c。确有另一 POSIX Shell 时按实际解释器处理，不能反过来假定任何目标都没有 /bin/sh。

历史重定向形式有 >file、1>file、2>file、8>file（合并输出）及其追加形式，输入为 0<file。对应版本要求重定向在末尾且符号与文件名间无空格，多重重定向可能只采用最后一项；确认当前规则后使用，不套用 2>&1。

确认可用命令和参数用 help 或 help <cmd>。过滤和逻辑优先在主机处理；本地 Shell 引用与目标解析分别检查，防止占位符、反引号或变量被本地主机意外展开。

不要把 Ctrl+X 等控制字符作为常规中断手段；某些目标可能将其解释为重置。需要中断、信号或重启时核对实际作用和任务授权范围。
