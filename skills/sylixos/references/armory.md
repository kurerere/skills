# Armory 制品管理

只问用法或接口时读取 [docs.md](docs.md)，不进入发布流程。打包、安装验证和发布是不同操作，按当前任务范围选择。

## 当前项目流程

先读项目的 Armory 配置、Makefile、发布脚本与目标配置，核对 CLI --help。包名、版本规则、平台、最低系统版本、文件布局和依赖来自当前项目，不套用 Node 的值。

- 打包前核对版本与元数据、已构建架构、预期内容和目标运行库。符号检查遵循项目规范，不强制所有 ELF 使用同一依赖集合。
- 需要 strip 时保留原始符号产物，并选择匹配架构/ABI 的工具。大小变化不是正确性证据。
- 先在临时目录检查归档成员、权限、链接和解包结果，避免意外覆盖；只有项目明确采用根目录安装布局时才准备相应包。
- 安装前确认目标、覆盖范围与回滚条件，检查安装结果并执行项目要求的加载和功能验证；清单存在不等于运行正确。
- 发布须在任务授权范围内，遵循项目 autoPublish 等限制。不能因脚本提供 --force 就把它视为用户授权；发布或 release 脚本也可能修改版本、提交 Git 和创建标签，调用前检查范围。
- 如需改变 CLI 配置，先保存实际旧值，结束后恢复旧值，不假定原值为 false。远端发布可能部分完成，本地回滚不代表远端已撤回，先核对远端状态再决定重试。

报告包版本、架构、实际检查、目标运行和远端发布状态，明确未完成阶段。项目使用 Node 的旧脚本布局时可读取 [armory-node.md](armory-node.md)，仍以当前脚本为准。
