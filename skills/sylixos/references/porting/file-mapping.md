# 文件映射与文件写入的一致性

文件读取正确但既有映射仍旧、数据库元数据异常或考虑 remap/msync 时读取。以下是移植检查方法，不是对所有 SylixOS 内核、文件系统和映射方式的缺陷结论。

## 区分观察与原因

分别比较写前映射、写后文件读取、写后原映射和新映射的实际字节。先读映射再写文件的序列与先写文件再创建映射是不同检查，不可互相替代。

旧映射陈旧、地址类似指令或数据库报页状态错误，都不能独立证明物理帧错误或同一个根因。要核对对应的源码、映射状态和数据，并把推测与目标观察分开记录。

## 可靠复现

- 记录内核、SDK、架构、文件系统、页大小、映射权限和运行时版本，检查截断、映射、定位写入的返回值和完整写入长度。
- 确保首次读发生在写之前且确实执行。C volatile 访问或让读值可观察有助于避免预触页读被消除，必要时核对生成代码。volatile 不修复文件一致性，也不是跨线程同步手段。
- 按实际旧内容和写入模式计算预期差异。4096 字节的 `(unsigned char)(i ^ 0x5a)` 中每隔 256 字节有一个 0；全零旧页恰有 4080 个不匹配，并非连续前 16 字节相同。计数不能替代实际字节检查。
- 分别验证映射写→文件读、文件写→新映射读等方向，不用单一序列宣称所有方向都损坏。

## 选择适配方案

由当前实现和目标证据选择候选，不能记成“调用两次 mmap 就能修复”的通用规则：

- 定位读取与页缓存：检查写后失效、不可变页面、事务快照、引用生命周期、并发填充、跨进程写入假设及内存/性能。
- 堆缓冲：检查刷新时机、覆盖范围、引用有效期和数据库规模下的内存需求。
- 映射失效：先验证目标是否支持并能正确刷新写入范围，核对页对齐、并发读者、别名与错误返回。只读映射的失效方案不能直接推广到含未写回修改的可写映射。
- 重新映射：检查旧指针失效、锁、资源回收、文件增长和重复操作稳定性。新映射能读新内容不证明长期 remap 安全。

一致性和持久性分开验证。数据库回归覆盖多次提交、重开、并发读写、文件增长及任务所需的快照/恢复。缺少当前目标证据时只报告已检查的实现和待验证候选，不宣称内核修复或目标验收通过。
