# 匿名堆页回收

移植运行时的 sysUnused/scavenger，或释放统计增加而物理内存不恢复时读取。文件映射一致性另见 [file-mapping.md](file-mapping.md)。

## 问题与现象

历史 Go 移植中，sysUnusedOS 曾为空实现：运行时记录了堆页释放量，物理页却仍驻留。底层 mmap 的行为也不能直接按常见系统的重映射语义套用，仅以原权限再次映射不足以完成回收。

## 当时的处理思路

在已可丢弃内容的匿名私有堆区间，连续两次固定地址 mmap：先改为 PROT_NONE，触发旧物理页失效与回收；再恢复 PROT_READ | PROT_WRITE，保留地址范围，后续访问重新缺页装入零页。

后续项目自行核对当前内核是否支持上述语义，再选择适配方式，验证实际回收和再使用时的清零保证。该方案只适用于运行时拥有且内容可丢弃的范围，不能用作文件映射一致性的通用修复。
