# 匿名堆页回收

移植 Go 等运行时的 sysUnused/scavenger、释放量增加而目标物理内存不恢复，或用固定地址 mmap 回收堆页时读取。文件写入与既有映射的一致性另见 [file-mapping.md](file-mapping.md)。

## 回收与地址保留

sysUnused 表示运行时不再需要某段内存的内容，但仍保留地址范围供以后使用。空实现可能让运行时的释放统计增加而物理页仍驻留；统计变化不能证明内核已经回收。

在目标缺少适用的 madvise 语义时，可调查固定地址匿名私有映射的候选序列：先将同一范围改为 PROT_NONE，再恢复 PROT_READ | PROT_WRITE，两次都带 MAP_FIXED。它依赖内核在权限变化时丢弃旧物理页、随后按需提供零页；调用两次本身不是充分条件。同权限重映射是否丢弃旧页，必须由目标实现和实测确认。

这是匿名堆页的适配线索，不能直接套到文件映射一致性、共享内存或仍有活跃引用的数据上。

## 使用前核对

- 确认该范围已由运行时拥有、内容可以丢弃且没有并发访问；两次调用之间不可访问该范围。MAP_FIXED 只能作用于明确拥有的地址范围。
- 地址和长度按实际内核页大小对齐；逐次检查返回地址与错误。第二次失败时范围仍可能不可访问，按运行时错误契约处理。
- 核对内核的同权限与权限变化分支、部分范围拆分、跨映射节点处理及失效接口的基址要求。接口能接收指针不代表它接受任意堆内地址。
- 核对 sysUnused/sysUsed 与清零契约。只有目标确实保证再使用得到零页，才能省去显式清零；恢复访问权限不等于已经分配物理页。

## 目标验证

对已写入非零内容的页执行回收，在进程仍存活且尚未重触页时检查目标物理内存，再按运行时契约重新启用并检查零填充及正常读写。分别观察 runtime 统计和系统物理页指标。

覆盖实际支持的页大小、子范围与相邻活跃页、跨节点范围及反复回收/重用。业务压力测试用于检查运行时回归，不能替代物理页回收和零填充检查。历史提交中的测试说明只作为线索；缺少原始日志或本次目标结果时，报告源码核对范围。
