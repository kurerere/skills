# V8 recipes

## Add a real SylixOS platform layer

**Signature:** V8 or Abseil selects an unrelated POSIX implementation, lacks
page/time/memory primitives, or tries to use an unsupported signal-stack sampler.

**Recipe:** Define `V8_OS_SYLIXOS`, provide
`deps/v8/src/base/platform/platform-sylixos.cc` for page size, time, and virtual
memory primitives, and select it from the V8 build. Scope sampler behavior to the
facilities SylixOS actually implements.

**Validation:** Build the host tools and ARM64 target without borrowing Linux
feature macros, then run the Node version gate, basic JavaScript execution, and
the V8/JIT smoke coverage used by the target test pipeline.

## Keep ARM64 JIT code close without oversized reservations

**Signature:** The default 256–512 MB V8 CodeRange fails with `ENOMEM`; disabling
CodeRange avoids that allocation but later produces invalid ARM64 `BL` targets
because generated code and builtins can be more than ±128 MB apart. A disabled
contiguous SegmentedTable can also leave a null or invalid base.

**Recipe:**

- Keep `kPlatformRequiresCodeRange = true` on SylixOS ARM64.
- Set the SylixOS maximal CodeRange to 16 MB (4096 pages, minimum 3 MB).
- Keep SegmentedTable contiguous memory enabled and use an 8 MB SylixOS
  reservation.

These values are a paired invariant: the CodeRange must fit the process limit
and ARM64 branch window, while the SegmentedTable must retain a valid base.

**Protected behavior:** Pointer compression and JIT tiers remain enabled; the
recipe does not trade correctness for an interpreter-only build.

**Validation:** Require successful startup under the target memory limit, JIT
execution with Maglev/Sparkplug/TurboFan still configured, and repeated runs
without the historical out-of-range PC signatures or null SegmentedTable base.
