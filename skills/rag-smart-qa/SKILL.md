# RAG 智能问答

## 概述

纯 RAG MCP 驱动的智能问答。**固定流程：先调用 `mcp__rag_mcp__list_knowledge_bases` 查询当前用户可见的知识库，再调用 `mcp__rag_mcp__search_knowledge_base` 检索**，基于检索到的原文内容回答用户问题，尽量不修改原文意思。支持图片自动渲染。

**核心原则：基于原文，不编造，不修改原意。无匹配时明确告知，不回退到自身知识。不预设默认知识库。**

## 何时使用

- 用户需要对知识库文档进行问答
- 常见场景：云枢、acohub、sylixos、vsoa 等产品的文档/知识库问答

## 工作流程

### Step 1: 查询知识库列表

**每次问答都先调用 `list_knowledge_bases()`**，获取当前用户可见的知识库，用于确定检索范围。

```
list_knowledge_bases()
```

返回：`[{id, name, description}, ...]` — 当前用户可见的知识库列表（共享知识库 + 本人创建），每次最多返回 1000 个。

基于列表确定检索范围：

| 场景 | 行动 |
|------|------|
| 用户明确提到知识库名称（如「云枢」「vsoa」「sylixos」） | 用 `knowledge_base_name=[<该名称>]` 进入 Step 2 检索；名称不在列表中也按其检索（服务端按名称精确匹配同名库） |
| 用户未指定知识库 | 基于列表语义判断最相关的知识库，用 `knowledge_base_name=[<相关名称>]` 检索；无法判断时跨全部库检索（不传 knowledge_base_name） |

规则：

- 返回的列表即**当前用户可见范围**（共享知识库 + 本人创建），与检索可见范围一致
- **列表结果只用于内部决策（辅助选库），不要输出给用户看**
- 不假设默认知识库，每次问答都重新确定范围

### Step 2: 调用 RAG MCP 检索

```
search_knowledge_base(query=<核心关键词>, knowledge_base_name=[<知识库名称1>, <知识库名称2>, ...], knowledge_ids=[], top_k=5)
```

| 参数 | 规则 |
|------|------|
| `query` | 用户问题的核心关键词 |
| `knowledge_base_name` | **字符串数组，支持传多个名称**。用户明确提到知识库名称时填此参数（如 `["云枢"]` 或 `["云枢", "vsoa"]`），按名称精确匹配并检索所有同名知识库；未指定则不传（Step 1 基于列表选出的名称填此） |
| `knowledge_ids` | 16 位十六进制 ID 列表。用户未指定范围时留空（空数组）跨全部知识库检索；名称请用 knowledge_base_name，勿填此处 |
| `top_k` | 默认 5。如果答案不充分可提升到 10（单次请求上限） |

| 返回情况 | 判定 | 行动 |
|---------|------|------|
| 连接超时 / HTTP 5xx | 服务异常 | 重试一次；仍失败 → "RAG-MCP 服务当前不可用，无法检索知识库内容” |
| 返回空数组 `[]` | 非失败，查询成功但无结果 | **不走异常流程**，直接进 Step 3 评估（判定为无匹配→Step 5） |
| 有返回但内容不相关 | 非失败，RAG 召回率低 | **不走异常流程**，进 Step 3 评估（判定为部分相关/无匹配） |

- **不要**基于自身知识或记忆去编造答案

### Step 3: 评估检索结果

对返回的文档片段集合进行语义匹配度判断：

| 场景 | 判定标准 | 行动 |
|------|---------|------|
| **高度相关** | 返回结果中包含直接回答用户问题的原文片段（段落/条目级别） | → Step 4，基于原文回答 |
| **部分相关** | 返回结果中有少量关联信息但不完整 | → **优化 query 后再检索一次**（最多 1 次），仍不足则如实说明信息缺口。优化策略：去掉过于具体的限定词、将专业术语替换为同义词或上位概念、拆分复合问题为单个关键词重新检索 |
| **无匹配** | 返回结果为空、或所有片段与问题语义完全不相关、或只包含无关元数据 | → Step 5，使用标准话术 |

**关键规则：**
- **"不匹配"必须严格判定** — 宁可说"无相关知识"，也不要基于模型自身知识去编造答案
- 如果检索结果包含多个片段，合并分析；不同片段间存在矛盾时如实说明
- **识别文档类型偏差**：RAG 可能返回快速入门概览（如 PDF Quick Start）而非详细操作页。当所有结果来自同一篇概述性文档、缺少具体步骤编号和操作细节时，判定为"信息不足→部分相关→优化后仍不足→诚实说明缺口"，不要基于概述内容推导操作步骤

### Step 4: 基于原文回答

**直接输出原文内容作为回答主体**，不使用分段标签包裹。回答底部附上参考文档来源。

格式：

```
<直接呈现检索到的原文内容，保留原格式、术语、结构。不做改写、翻译或缩写，尊重原文事实。原文较长时截取与问题直接相关的段落。如有图片，直接渲染。>

—
【参考文档】
- 知识库名 / 文档名
```

**回答要求：**
1. **忠实原文**：保持原文的表述、术语、格式、编号不变。不要转化为简洁要点，不要压缩、提炼、概括成要点，不要丢失细节（步骤、数字、条件、注意事项），原文多详细就多详细
2. **保留结构**：原文是表格/列表/代码块，回答中也要保持相同结构
3. **保留图片**：逐条检查检索结果的 `content` 字段，找出所有图片引用并渲染。识别特征：以 `.jpg` `.jpeg` `.png` `.gif` `.webp` `.svg` 结尾的 URL，或路径含 `/media/`、`/api/rag-server/media/`。无论原文是裸 URL 还是已带 `![]()`，都统一转成 `![](URL)` 语法输出，渲染在相关段落旁，一张不漏。格式参考
![](/api/rag-server/media/fcfebab1c83f4bdf/4b3c7f3beb0a48c4/a4084ee6f663907d433f5238e8141c8c58f6acb84a5e3ba76d5b7cd664a55677.jpg)
4. **自然呈现**：直接输出内容，不要用「根据原文」「检索结果显示」等引导语包裹
5. **参考文档**：回答底部以分隔线 + 列表列出来源文档
6. **补充说明**：仅当原文信息不足以完全覆盖问题时，在底部标注「以下内容基于模型知识，非知识库原文」后补充解释

### Step 5: 无结果时的标准话术

当 Step 3 判定为"无匹配”时：

```markdown
关于「<用户原始问题>」，当前知识库中无相关知识，无法回答。
```

## 常见陷阱

1. **用通用知识代替原文。** 最大禁忌。即使你对某个话题非常了解，也必须以 RAG 检索到的原文为准。

2. **把原文简化成要点。** 不要压缩、提炼、概括，原文多详细就答多详细，细节（步骤、数字、条件、注意事项）不能丢。

3. **修改原文意思。** 不要「润色」或「优化」原文表述。紧密转述可以，但不能改变原意。

4. **假设默认知识库。** 每次问答都必须**先调用 list_knowledge_bases() 获取当前用户可见的知识库，再检索**，不要直接跨全部库盲检索，也不要凭记忆猜库名。该列表仅用于内部辅助选库，**不要展示给用户**。

5. **忽略图片。** 检索结果中如果有图片引用，必须渲染。检查每条结果的 `content` 中是否包含图片路径（`.jpg/.png/.gif/.webp/.svg` 结尾或含 `/media/`），并把裸 URL 转成 `![](URL)` 输出。

- [ ] 直接输出原文内容作为回答主体，未使用分段标签包裹
